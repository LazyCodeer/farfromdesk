# Social assistant: Meta feasibility and prototype boundary

Verified against official documentation on 30 October 2026. This is a design and test prototype, not a live integration. Account availability, pricing, policies, API versions and limits must be checked again before implementing or enabling a real provider.

## Meta Model API

- Meta documents [Muse Image](https://dev.meta.ai/docs/image-generation), model `muse-image-1.0`, for generation and editing via the Responses API or `POST https://api.meta.ai/v1/images/generations` and `/v1/images/edits`. It returns base64 or a temporary signed URL. The documented default is WebP; JPEG is available. It bills $0.01 per successfully returned image at the time checked; verify current pricing and account limits before use.
- [Quickstart](https://dev.meta.ai/docs/quickstart) requires a Model API account and API key. The [models page](https://dev.meta.ai/docs/models) says availability may vary by country. Having a Meta social account does not establish Model API access, entitlement or billing setup.
- Image generation can perform web/image search and run code by default; the [image guide](https://dev.meta.ai/docs/image-generation#tool-controls-images) documents controls to disable those. The Responses API stores conversations by default; `store: false` is documented. Treat prompts and references as information sent to Meta; obtain the owner's intended setup and permission before live use. Do not silently substitute a non-Meta image provider.
- Meta documents [search grounding](https://dev.meta.ai/docs/search-grounding) for text models; this is separate from the Instagram social graph. A real research adapter needs source links, dates, evidence and explicit failure/empty states. Sample angles in this prototype are not research and have no sources.

## Instagram publication

- The [Instagram overview](https://developers.facebook.com/documentation/instagram-platform/overview) requires a professional (business or creator) account, developer registration and a Meta app. Meta recommends Unified Login for new integrations; it requires a business portfolio but no Facebook Page. Instagram Login does not require a Page; Facebook Login does. These paths have different tokens, hosts and permission families.
- Standard Access is described for accounts owned or managed by the app; Advanced Access for other users' accounts requires App Review and Business Verification. Required access, permissions and account eligibility must be confirmed for the actual setup. The [publishing guide](https://developers.facebook.com/documentation/instagram-platform/content-publishing) lists tokens and permissions by login type, plus Page Publishing Authorization where applicable.
- Publishing involves creating a media container and publishing it. The guide says image media must be publicly accessible for Meta to fetch, supports JPEG, and provides an `is_ai_generated` disclosure field. Public hosting itself is a disclosure and must be designed and authorized separately. The guide lists a 100-post rolling 24-hour limit, but a carousel section on the same page says 50; query the platform limit and verify the applicable current policy rather than hard-coding either number. Check container status, errors and uncertain outcomes before any retry.
- This verifies Instagram professional-account publishing only. No capability is claimed for personal profiles, Facebook Pages, Threads, LinkedIn or other platforms until their own current official integration requirements are verified. No scheduling is implemented.

## Local implementation and review limits

See the [owner boundary assessment](social-owner-boundary.md) for the current threat model, manual handoff and prerequisites for a signed native broker.

The Local-only `Social` tab saves, paginates, edits and deletes drafts. It warns about unsaved changes before sidebar navigation and desktop window close. The close guard has only been tested with a mocked desktop lifecycle; a real native-window test is still needed. Draft deletion removes the row from the active database but is **not secure erasure**: SQLite free pages, the write-ahead log, filesystem snapshots and backups can retain previous content. Same-user coding sessions may be able to read or modify Local state, including drafts and the app's admin token; this patch does not create an operating-system identity boundary.

**Live social provider calls and Instagram credential storage and publishing are disabled.** Independent review found that same-user coding sessions can read the Local admin token and existing Meta key; a server nonce plus a client-supplied confirmation cannot prove the owner approved an action. POSIX file mode 0600 does not protect an Instagram token from these sessions. The native-admin endpoints reject live research, caption generation, image generation, account configuration, media preparation and publication even if a caller supplies a confirmation. No real social account or credential was accessed. The separate design preview uses only fictional data. Mock-only adapter tests cover Meta request shapes, paid-call concurrency, uncertain outcomes and image handling; these adapters are not wired to live social routes. A request that was running when a process stopped remains blocked: automatic recovery is deliberately disabled until exclusive recovery can be verified.

Before any live action is enabled, implement and independently verify a genuinely owner-controlled authorization and credential boundary for the actual Local threat model. Explicit authorization must bind each publication to its destination and final content. Meta fetches the public URL when preparing media, and a URL or container ID alone does not prove the exact image bytes Meta fetched. A future publishing implementation must solve this media verification problem, handle uncertain outcomes without automatic retry, and get separate authorization for any public hosting. Verify actual account access, API version, permissions, rate limits and pricing before use.

Neither live provider behavior nor native packaging has been verified. Other platforms, videos, carousels, automatic scheduling, automatic hosting and OAuth onboarding are not implemented.
